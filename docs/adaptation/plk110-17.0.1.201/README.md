# PLK110 / ColorOS 17.0.1.201 adaptation record

Firmware-specific adaptation of this tree to **OnePlus 15 (PLK110, CN, project 24831)** running
**ColorOS 17.0.1.201(CN01C20P01)**, OTA `PLK110_11.C.80_1800_202610290542.97.8cf4de15`.

This branch set does not change kernel semantics: it re-anchors three firmware-identity values so a
`boot.img` built from this tree carries *your* firmware's identity instead of the one the upstream
author tested (`CPH2745IN 17.0.0.102`).

## 3. Verification performed before committing

### 3.1 Symbol contract (zero-build, exact)

`tools/plk110/` reproduces this without `repo sync`, compiler or build:

1. `erofs_extract.py` unpacks `system_dlkm.img` (EROFS, uncompressed) → 103 modules incl. `rust_binder.ko`.
2. The 1,069 stock `.ko` files yield 6,681 distinct `MODVERSIONS` records; 5,934 are provided by
   sibling modules, leaving **4,267 symbols that must come from vmlinux**.
3. `kcrctab_extract.py` walks `__ksymtab`/`__ksymtab_gpl` (both `SORT()`ed by name in
   `include/asm-generic/vmlinux.lds.h`) and reads `__kcrctab`/`__kcrctab_gpl` straight out of the
   `Image`; `verify_image.py` renders the verdict.

| Image | exported | required | matched | missing | CRC mismatch | verdict |
|---|---|---|---|---|---|---|
| stock `6.12.69-g5fd3960…` | 9,933 | 4,267 | 4,267 | 0 | 0 | PASS (baseline self-check) |
| upstream `6.12.117-o-g9218fe3…` (release sha256 `3cef6c67…`) | 10,172 | 4,267 | 4,267 | 0 | 0 | PASS |

Conclusion: the KMI/MODVERSIONS contract of this firmware is satisfied by kernels built from this
tree. Any locally built `Image` must be re-checked with the same two commands.

### 3.2 Structural comparison against the upstream firmware

1,069 vs 1,070 modules (upstream has `oplus_bsp_storage_io_metrics`, absent on CN);
966 name-matched modules, 926 (95.9 %) with an identical import/export surface; 40 differ, mostly
`oplus_bsp_*` plus `cfg80211` / `mac80211` / `zram` / `camera_extension`.

## 5. Build

```sh
repo init -u <this fork> -b plk110-17.0.1.201-<variant> -m oneplus_15.xml
repo sync -c -j8 --no-clone-bundle          # fills the 10 kernel_platform/prebuilts/* projects

cd kernel_platform
tools/bazel build --jobs=4 --config=local --kbuild_symtypes \
  //common:kernel_aarch64 \
  //common:kernel_aarch64_abi_dump \
  //common:kernel_aarch64_abi_kmi_symbol_checks
tools/bazel build //soc-repo:canoe_perf_avb_sign_boot_image
```

Toolchain must be the pinned prebuilts (`clang 19.0.1 / 14043575`, its Rust and bindgen): the CRCs
are produced by `GENDWARFKSYMS` from compiler-generated type strings, so substituting a system
clang invalidates the contract.

## 6. Flash and rollback

Only `boot` may be flashed. Keep stock `vendor_boot`, `init_boot`, `vendor_dlkm`, `system_dlkm`,
`dtbo`, `vbmeta`.

```sh
adb shell su -c "dd if=/dev/block/by-name/boot_a of=/sdcard/boot_stock_a.img"
adb pull /sdcard/boot_stock_a.img          # sha256 must be a1596626…
fastboot flash boot_a boot.img
fastboot reboot
# rollback
fastboot flash boot_a boot_stock_a.img
```

Post-flash checks: `uname -a`, absence of `disagrees about version` / `Unknown symbol` in `dmesg`,
PIN unlock (F2FS inlinecrypt + dm-verity), camera, calls, fingerprint, USB sharing, WLAN.

## 7. Limits

* Boot-only. The DLKM partitions built by `canoe_perf_dist` are **not** qualified for flashing;
  replacing them requires re-signing `system_dlkm` / `vendor_dlkm` and rebuilding `vbmeta`.
* The AVB key is the upstream test key — unlocked bootloader only.
* Module-signature verification: `CONFIG_MODULE_SIG_FORCE` is not set, so the swapped trust anchor
  mainly affects module-signature bookkeeping, not loadability.
* Runtime qualification (suspend, OTG, repeated boots, TWRP decrypt) is out of scope here, exactly
  as in the upstream releases.
